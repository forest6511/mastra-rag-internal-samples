本番環境のデプロイ手順は、まず前営業日までに `#dev` で本番切替の日時を告知し、承認者（小林）の了承を Jira の課題に残します。[1]  
その後、踏み台サーバーに SSH でログインし、`/opt/kanade-yoyaku` に移動して `./deploy.sh production` を実行します（約10分）。[1]  
最後に、ヘルスチェックの URL `/healthz` が 200 を返すことを確認し、完了を `#dev` に投稿します。[1]  
失敗した場合は `./rollback.sh production` を実行して直前の版に戻し、戻したことを `#dev` に報告します。[1]

補足として、2026-09-01 の kanade-infra README では、本番デプロイは GitHub Actions で行い、踏み台サーバーの `deploy.sh` は廃止したとあります。[3]  
したがって、資料間で手順が食い違っており、より新しい 2026-09-01 の資料では旧手順が廃止前のものとされています。[3]
