本番環境のデプロイ手順は、2025-06-10 の資料では「前営業日までに #dev で本番切替日時を告知し、承認者（小林）の了承を Jira 課題に残したうえで、踏み台サーバーに SSH でログインし、`cd /opt/kanade-yoyaku`、`./deploy.sh production` を実行、`/healthz` が 200 を返すことを確認して #dev に完了投稿する」という手順です。[1]

ただし、2026-09-01 の資料では本番デプロイは GitHub Actions に変更され、踏み台サーバーの `deploy.sh` は廃止されたとあり、Confluence の手順は廃止前の手順だとしています。[2]

したがって、現在の手順は「`v` で始まるタグを打つと `deploy-production` ワークフローが承認待ちになり、小林が承認するとデプロイされる。デプロイ後はワークフローが `/healthz` の 200 を確認する」です。[2]
