# 第11章 答えが合っているかを数字で確かめる: 評価セット

「良くなった気がする」ではなく、数字で確かめます。18問の質問と、答えに入るべき要点・材料に入るべき資料を評価セットとして書き、生成 AI に採点させて、3回の平均と幅で読みます。

## この章で要るもの

- 第4章の DB と、5つのサービスの資料（記録した結果を集計するだけなら不要）
- OpenAI の API キー（評価を自分で回すときだけ）
- 費用: 評価を自分で回すと、18問 × 3回で約 $3（採点に `gpt-5.5` を使う場合）。記録した結果を集計するだけなら、費用はかかりません

## この章で使うファイル

- `eval/questions.yml` — 評価セットの18問と、答えに入るべき要点
- `eval/expected-docs.yml` — 質問ごとに、材料に入るべき資料
- `eval/runs/` — 評価の結果。`ch10.jsonl` は第10章の作りの著者の結果、`final-v4.jsonl` は本書の最後の作りの結果
- `src/eval/run.ts` — 評価を回す（`npm run eval -- <ラベル>`）
- `src/eval/judge.ts` — 生成 AI で採点する
- `src/eval/summary.ts` — 結果の表を出す（`npm run summary -- <ラベル>`）

## 始める前に

```bash
cd ../ch11-eval
npm ci --ignore-scripts
cp ../ch10-permissions/.env .env
```

評価を自分で回すときは、第10章までの索引が入った DB を使います。DB は、第4章の `ch04-setup` で起動したものを使います（[ルートの README](../README.md#db-について)）。止めている場合は、`ch04-setup` で `docker compose up -d` を打ちます。

## 手順

記録した結果を集計します。キーも費用も要りません。

```bash
npm run summary -- ch10
npm run summary -- final-v4
```

評価を自分で回すときは、著者の結果（`ch10`）と別の名前を付けます。同じ名前だと、書き終えた行としてすべてスキップされます。

```bash
RECORD=1 npm run eval -- my-ch10
npm run summary -- my-ch10
```

答えと採点は、記録にあればそこから返るので、著者と同じ材料・同じ答えになった分は、費用がかかりません。`RECORD=1` は、新しく作った答えと採点を `records/` に残し、次に回すときに費用をかけないための設定です。`git status` に `records/` の差分が出ます。元に戻すときは `git checkout records/` を打ちます。

## 確かめ方

- `npm run summary -- ch10` の結果が `out/summary-ch10.txt` と同じになる
- 平均だけでなく、3回の幅（ばらつき）と、検索の指標（材料に正解の資料が入ったか）を見て、原因が検索か答えかを切り分ける

## キー無しで確かめる

アカウントや API キーが無くても、この章のテストは回ります。記録した答えと採点だけで、評価の集計が書籍と同じになることを確かめます。DB も費用も要りません。

```bash
npm test
```

書籍に載せた実行結果は `out/` にあります。

## 後片付け
