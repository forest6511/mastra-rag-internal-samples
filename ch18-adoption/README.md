# 第18章 導入を決める: 稟議の1ページ・規約・自社データへの置き換え

この仕組みを社内で試すために、上司に出す稟議の1ページと、情シスに渡すチェックリストを作ります。数字は、どれも本書で測った値で埋めます。カナデループの資料を、自社の資料のディレクトリに置き換える方法と、検証用のアカウントの消し方も扱います。

## この章で要るもの

- 稟議とチェックリストは、ファイルを読むだけです（費用なし）
- 自社の資料を取り込むときは、第4章の DB と OpenAI の API キー
- 費用: サンプルのテストは費用がかかりません。自社の資料を取り込むと、本文の埋め込みに OpenAI の API の費用がかかります（試作で索引に入れた61件で約 $0.0005）

## この章で使うファイル

- `ringi.md` — 稟議の1ページのひな形。〈 〉の中を、自社で測った値か出典のある値で埋めて使う
- `ringi-example.md` — カナデループの数字で埋めた例（書籍 図 18-1）
- `checklist.md` — 情シスに渡すチェックリスト（データの行き先・学習への利用・保持期間・質問ログ・削除と権限の反映など）
- `src/sources/` の `files` — 手元のディレクトリの資料を取り込む（`FILES_DIR`）
- `test/files.test.ts` — ディレクトリの取り込みのテスト

## 手順

稟議を書くときは、`ringi.md` をコピーして埋め、`ringi-example.md` と並べて、効果・費用・リスク・できないことの4つが、すべて数字か根拠付きで書けているかを確かめます。

自社の資料を取り込むときは、資料を置いたディレクトリを `FILES_DIR` に入れます。

```bash
cd ../ch18-adoption
npm ci --ignore-scripts
cp ../ch16-aws/.env .env     # 第16章までの値（DB と OpenAI の API キー）
FILES_DIR=/path/to/company-docs npm run sync -- files
```

`FILES_DIR` を入れると、5つのサービスに加えて、このディレクトリも取り込みます（第9章の差分同期と削除も、そのまま効きます）。`npm run sync -- files` のように名前を付けると、ディレクトリだけを取り込みます。

> [!WARNING]
>
> - 取り込めるのは Markdown（`.md`）のファイルだけです
> - `acl.yml` に書いていない置き場所の資料は、既定（`default`）の全社員に見えます。人事などの資料を入れる前に、`acl.yml` に `files:<一番上のディレクトリ名>` で見てよいグループを書きます
> - 自社の資料を取り込むと、本文が OpenAI の API に送られます（埋め込みのため）。取り込む前に、`checklist.md` の項目を情シスと確かめてください

## 確かめ方

- `npm test` が通る（ディレクトリの取り込みのテストを含む）
- 稟議の1ページの4つの欄が、すべて測った数字か出典付きで埋まっている

## キー無しで確かめる

アカウントや API キーが無くても、この章のテストは回ります。記録した応答だけで、ディレクトリの取り込みを含む全体を確かめます。DB も費用も要りません。

```bash
npm test
```

書籍に載せた実行結果は `out/` にあります。

## 後片付け

取り込んだ自社の資料は、`FILES_DIR` を外しても索引に残ります。消すときは、`files:` で始まる資料を DB から消します（チャンクも一緒に消えます）。

```bash
docker compose -p ch04-setup exec db psql -U rag -d rag \
  -c "DELETE FROM documents WHERE id LIKE 'files:%'"
```

## 検証用のアカウントを消す

本書を読み終えたら、検証のために作ったものを消します。

1. 各サービスのトークン・API キーを取り消す（第4章の後片付け）
2. AWS の構成を `npx cdk destroy` で消す（第16章のクリーンアップ）。`cdk bootstrap` で作ったスタック（CDKToolkit）と、デプロイのために作った IAM ユーザーとアクセスキーも消す
3. Slack のワークスペース・Notion のワークスペース・Atlassian のサイト・GitHub の Organization を、それぞれの管理画面から削除する
4. 手元の DB を、`ch04-setup` で `docker compose down -v` で消す
