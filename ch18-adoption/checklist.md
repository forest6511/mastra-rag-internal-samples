# 情シスに渡すチェックリスト（12項目）

確認日と、各社の規約・データの扱いのページの URL を、項目ごとに残す。

1. データの行き先: 元のサービスの API → 自社の DB → 埋め込みの API（取り込みのときに全資料の本文）→ 答えの API（質問と材料の資料）→ Slack、の各区間と、データを置く国を書き出したか。Claude・ChatGPT のアプリから使う場合（第15章）は、そのアプリの会社にも質問と検索の結果が渡る
2. 学習への利用: 生成 AI の API に送ったデータが、既定で学習に使われない設定であることを、管理画面で確かめたか。Claude・ChatGPT のアプリから使う場合は、利用者のプランごとの学習と保持の設定を確かめたか
3. 生成 AI の側の保持期間: 既定の保持（30日など）で良いか。ゼロ保持（ZDR）が要るか
4. 自社の側の保存物: 資料の本文・埋め込み・URL・権限を、どの DB に置き、暗号化とバックアップをどうするか
5. 質問ログ: 何を・何日残し・誰が見られるか。本人から消してほしいと言われたときの手順
6. 元の資料の削除の反映: 元のサービスで消した資料が、何時間以内に索引から消えるか
7. 権限の反映: 元のサービスで見られない人に、その資料が答えの材料にならないか。異動・退職の反映が何日遅れるか
8. 社外の人がいる Slack のチャンネル: Slack コネクトのチャンネルにアプリを招いていないか（取り込みはアプリが参加しているチャンネルを全部読む）。ボットがそこで答えないか
9. トークンの権限: 読み取りだけ・対象を絞ったトークンか。置き場所（Secrets Manager など）と更新の周期
10. 規約上の禁止: モデルの学習に使わない・公式の API だけを使う・レート制限を守る
11. 社外に出さない: このアプリを、子会社・取引先など組織の外に提供しない
12. 監査: 誰がいつ何を聞き、どの資料が材料になったかを、後から追えるか
